**Version 1.2.1 — GUIDED SIMULATION UI**。v1.2.0（作業開始時のコミット `348ad5e`）から改修しました。開始時のGit差分はありませんでした。GitHubへのpush・公開は行っていません。

## UI改善内容

上部は「概要／使い方／サンプル／シミュレート実行」の4タブです。選択状態を色と下線で表示します。狭い画面でも4項目を表示し、長い実行タブは2行にしています。スクロール中もメニューを操作でき、現在のタブを押しても画面の先頭へ戻れます。

概要の「おまかせ体験」はHTML・イベント・専用CSSから削除しました。概要には目的・主要機能と「サンプルを試す」「自分の条件でシミュレート」を残しています。

サンプルは番号・アイコン・名前・短い説明・展開アイコンを表示します。カードを押すと直下の読み取り専用条件を開き、同じカードで閉じ、別カードで前のカードを閉じます。開始・終了日、全運賃、曜日、祝日、土日オプション、休暇、個別有効／無効日、比較券種をサンプルデータから表示します。

読み込み後は入力画面の上部に、小さな設定済み案内・サンプル名・復元ボタンを表示します。従来の大きな「現在のサンプル」パネルは削除しました。案内と重複する復元ボタンは金額欄に表示しません。

金額入力には「片道1回分」「定期券1枚分」を説明し、往復は片道の2倍と明記しました。結果の金額は3桁区切り＋円表記・右揃えとし、同額は同額表示です。最安探索から外した券種の単独費用には「参考額（最安探索の対象外）」と表示します。

空欄・負数・小数の金額、期間の逆転、利用日ゼロ、券種ゼロは入力欄や設定群の近くに修正方法を表示します。入力変更時は古い結果・PDF選択を無効化します。カレンダーと線表は維持しました。

「運賃・定期代を調べる」を金額欄の近くに追加しました。指定のジョルダン・Yahoo!路線情報を新しいタブで開きます。元の入力は維持し、運賃の自動取得は行いません。

## サンプル操作フロー

1. サンプルカードで条件を展開して確認します。この時点では入力を変更せず、計算もしません。
2. 「この条件でシミュレート」を押します。最初の読み込み直前の入力・個別日・除外期間・入力途中フォーム・計算済み結果を退避します。
3. 「シミュレート実行」タブへ移り、サンプルの条件を一括反映します。古い結果は消去し、まだ計算しません。
4. 利用者が条件を確認・調整し、実行ボタンを押すと既存エンジンで計算します。結果の先頭へ移動し、今回の発見と使用サンプル名を表示します。
5. 「元の設定に戻す」で最初の退避内容を復元します。続けて別サンプルを読み込んでも元設定を上書きしません。再読み込み後も復元できます。

保存キーと既存設定の形式は維持しました。起動時に保存済み設定を不必要に削除しません。明示的な「初期化」は従来どおり全設定を初期値へ戻す操作です。

## 日本時間の翌日初期化

初回の未保存状態と、通常の「初期化」では開始日を **日本時間の翌日** にします。`Intl.DateTimeFormat` の `Asia/Tokyo` から年月日を取得し、日付として1日進めています。UTC日付の切り取りは使用していません。

終了日は従来の「開始日から6か月進めた日の前日」を維持しています。例：日本時間2026年11月1日の初期化では2026/11/02〜2027/05/01です。日本時間11月2日なら2026/11/03〜2027/05/02になります。

金額の初期値（片道633円、定期22,980／65,500／124,100円）と、曜日・除外・個別日などの初期化範囲は従来どおりです。サンプル中は専用の復元ボタンを使用します。

## PDFの各パターン出力対応

| 保存対象 | 対応 | データの出所 |
|---|---|---|
| 最安購入方法 | 対応 | 既存エンジンの最安フロー |
| 普通乗車券のみ | 対応 | 各有効日に往復費用で購入 |
| 1か月定期券のみ | 対応 | 既存比較処理と同じ順次購入 |
| 3か月定期券のみ | 対応 | 同上 |
| 6か月定期券のみ | 対応 | 同上 |
| すべてまとめて保存 | 対応 | 上記5パターンを区切って収録 |

金額付きの保存対象を選び、「選んだパターンを保存」を押します。既存と同じブラウザーの印刷機能を利用し、新しい画面でPDFとして保存します。自動で印刷画面が開かない場合は、出力画面内の「印刷・PDFに保存」を押せます。

内容は、ツール名、日本時間の出力日時、対象期間、全運賃、曜日・祝日・休暇・個別日設定、最安探索の対象券種、使用サンプル、選択パターン、総額、購入フロー、定期券の有効期間、普通券対応期間と実際の利用日一覧、注意事項です。

金額は円表記・桁区切り・右揃えです。日本語フォントはシステムフォントを使います。表の見出しを続きページにも繰り返し、行の途中の改ページを抑えています。パターン名・対象期間を含む保存名を文書タイトルと保存名候補に設定します。

## 購入フロー生成方法と金額整合性

最安探索のDP、`getNextNodeIndex()`、`createFlowStep()`、`getPatternOnlyCost()`、月加算のルールは変更していません。

- 最安案：既存の `result.flow` を用います。
- 単一券種案：最初の有効日を購入日とし、`getNextNodeIndex()` でその券種が対応する有効日まで進めます。同じ券種で最後の有効日まで繰り返します。これは既存の単一券種費用の計算と同じ処理です。
- 各購入には、券種、購入日、有効期限、実際の対象利用日、費用を付加します。最安フローの表示名だけを変更して流用していません。
- 定期券の計算上の有効期限は `addMonthsSafe(購入日, 月数) - 1日`。元のフローの終了日（最後に実際に通う日）と分けて表示します。対象期間の外まで有効でも、定期代を日割りにはしません。
- 普通乗車券が連続する購入手順は表示上まとめますが、期間内のすべての日に買う意味にはしません。「下記の対象利用日だけ」と明記し、対応日数・実日付・往復費用を併記します。
- 計算時点の条件を結果に保存し、PDFはその条件で作ります。別の金額入力を参照して、過去の結果のPDF金額だけが変わることを防ぎます。

保存前に全5パターンで、購入額合計＝比較額／最安額、有効日の順序・数・重複や漏れ、有効期限内での対応を検証します。不一致なら保存を止め、近くに再計算を促すエラーを表示します。

既存の比較欄と同様、単一券種の参考額は4種類すべてを算出します。最安探索で券種を外した場合も参考案のPDFを選べます。PDFには最安探索に使用した券種を明記します。

学生サンプルの実測例（2027/08/01〜2028/01/31）：

| パターン | 金額 | 購入手順の要点 |
|---|---:|---|
| 最安 | 104,746円 | 普通31日分＋3か月定期1枚 |
| 普通のみ | 117,738円 | 有効93日×往復1,266円 |
| 1か月のみ | 114,900円 | 1か月定期5枚 |
| 3か月のみ | 131,000円 | 3か月定期2枚 |
| 6か月のみ | 124,100円 | 6か月定期1枚 |

最安案の内訳は、9/1〜9/24のうち16利用日＝20,256円、9/27購入の3か月定期＝65,500円（計算上9/27〜12/26有効、実利用は12/24まで）、1/11〜1/31のうち15利用日＝18,990円です。合計104,746円と一致します。

`index.html` をPC Chromeで開きます。iPhone相当の確認は開発者ツールで幅375／390pxに切り替えてください。実機Safariでは同じWi-Fi上のローカルHTTP配信などで開き、印刷・共有の動作を確認してください。今回、LAN配信や公開サーバーへの配置は行っていません。
